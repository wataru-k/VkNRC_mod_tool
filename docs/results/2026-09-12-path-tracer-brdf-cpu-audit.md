# Path Tracer BRDF CPU invariant audit (2026-09-12)

## Scope

This is a CPU-only diagnostic of the equations currently implemented in
`shader/src/CookTorranceBRDF.glsl` and consumed by `BRDFStep` in
`shader/src/path_tracer.comp`. It is not a reference-render comparison and does
not certify the complete path tracer.

The reproducible checker is `tools/check-brdf-invariants.py`. It mirrors the
current GLSL equations, deliberately retaining their edge cases.

## Result

The audit failed five invariants:

1. A black material produces `0 / 0` in `CT_Specular_Prob`, hence `NaN`.
2. The implemented `Walter_G1` is not bounded by one. The deterministic sweep
   produced `976.5932548191041` for roughness `0.001`, `v_dot_n=0.001`, and
   `v_dot_h=1.0`.
3. In the broad PDF probe, 20,125 of 200,000 cases were non-finite. These were
   driven by the black-material probability case. No negative PDF was observed.
4. When directions were generated by the mirrored `CookTorranceSample`, 723 of
   200,000 samples were below the shading-normal hemisphere.
5. The same 723 sampled directions had zero/non-finite PDF. The shader later
   divides by this PDF and sanitizes the resulting non-finite color to zero.

Among positive, finite sampled PDFs, the largest observed single-step throughput
component was `463.1115882538905`. Its counterexample was:

- roughness: `0.05`
- `n dot v`: `0.00013456126539024282`
- `n dot l`: `0.13519067129780304`
- PDF: `3.4134297105974865`
- BRDF component: `11693.106036773626`

This is sufficient to show that the current implementation can generate large
finite path weights before NRC training. It does not prove that this exact
counterexample occurs in Bistro or that it alone causes WhiteOut.

## Interpretation limits

- The checker uses Python double precision. GLSL shader execution uses 32-bit
  float, so underflow/overflow boundaries differ. The broad probe observed a
  smallest positive PDF of about `1.3e-309`; such values cannot remain positive
  in float32. Consequently this CPU audit is conservative about float32 PDF
  underflow.
- The material set is synthetic and intentionally includes Bistro-like glossy
  roughness values. It is not sampled from the scene's actual hit distribution.
- The view directions are stress-distributed down to grazing incidence. A GPU
  capture is required to measure their frequency in the real scene.

## Next experiment

Before changing the loss or clipping NRC targets, record the following at the
path-tracer source for the top throughput/target tail:

- bounce index and material/primitive ID;
- roughness;
- `n dot v`, `n dot l`, and shading-normal/geometric-normal agreement;
- BRDF, PDF, and `BRDF * abs(n dot l) / PDF`;
- whether the sampled direction is below either normal's hemisphere.

This experiment requires a shader build but no GPU while implementing and
compiling it. Running the Bistro capture requires explicit GPU coordination.
